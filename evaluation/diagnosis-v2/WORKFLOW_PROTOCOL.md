# Frozen production-workflow comparison v1

Freeze before the first development call; freeze source hashes again before the first held-out call. This replaces no earlier study. Candidate is bounded-investigator-v5 with explicit originating-service semantics, narrow per-claim HTTP-status/reference checks and improved atomic-claim citation instructions. Baseline hybrid ranking and the frozen knowledge revision remain unchanged.

Run the actual Repository, SnapshotStore, EvidenceTools, worker.run_once, Toolset and LangGraph Investigator. Jobs/checkpoints/evidence persist in an isolated operator SQLite preview database for repeatable replay; this is not a PostgreSQL concurrency benchmark. Runbook search is the real local API/PostgreSQL/locked encoder, pinned to diagnosis-v2/knowledge.json's revision. Provider requests receive only anonymous snapshot observations, scoped guidance and reviewed topology, never capture labels, fault mode or filenames containing labels.

Development uses the four development instances not consumed by the earlier pilot (one of each family). Hold out all sixteen reserved instances until code, prompt, protocol, model, data and software hashes are locked. No changes after seeing held-out results. Fault families are shared between splits, so results measure controlled instance generalization, not unseen fault-family generalization.

Three methods share identical initial checkout evidence, incident text, topology, corpus/model/prompt and output schema: logs_only (one-shot, no runbooks), rag (one-shot plus production-baseline initial guidance), and agent (same initial RAG plus scoped native read-only tools). One-shot methods may only finish. Agent has at most three model calls, six tool starts and 120 seconds. Active tools can collect additional records from the independently captured complete three-service window. Log-only and RAG do not receive those additional records. This measures extra evidence gathering as well as reasoning, and agent cost can be higher.

Development cap: twenty provider starts, 640 KB serialized input and 150,000 provider-reported tokens. Held-out cap: ninety-two starts, 2,944 KB input and 700,000 reported tokens. Every request is bounded to 32 KB and 2,048 requested output tokens. Rate spacing is at least four seconds between starts; no automatic provider retry, alternate model, paid fallback or billing upgrade. Persist a reservation before invoking; preserve partial/error rows and stop the phase on provider error or budget exhaustion. Never overwrite a recorded phase or automatically repeat unknown outcomes. Application caps do not guarantee account-wide provider billing.

Held-out additionally has four active-agent ablations: the first held-out unavailable and slow instances with payment coverage removed, and the first unavailable and handler-error instances with runbook guidance unavailable. These are explicit missing-source/guidance ablations, not falsely labelled stale-runbook tests. Labels select ablation instances operator-side but do not enter provider context.

Primary metric: originating-service top-1 match on the twelve nonhealthy held-out instances per method. A correct row requires a validated generated report and first hypothesis.service == the frozen originating-service label. Invalid/partial/no-hypothesis rows count incorrect. Report counts and denominator, top-three match, completion, calls, reported tokens and elapsed time separately. Healthy behavior is four separate cases: require validated report, no hypotheses and inconclusive about an alleged failure. Do not combine those denominators into an invented universal accuracy percentage.

This typed label match is failure localization, not proof of the underlying cause or natural-language claim faithfulness. Narrow HTTP-status checks establish only their defined consistency condition. Qualitative same-assistant review records incomplete citations, unsupported underlying causes and inappropriate checks; it is not independent human grading. Do not publish an unsupported-claim/faithfulness percentage without an adequately specified complete review.

Record all failures and ablation limitations. Do not choose new prompts/rankers from held-out outcomes. External independently produced data and operational/load verification remain separate evidence. Publish the actual outcome even if RAG/agent adds no localization gain over caller logs.
