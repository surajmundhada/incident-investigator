# Evaluation results and reproduction

These are bounded historical experiments, not independent validation. Frozen inputs, raw outputs and failure records remain unchanged. Source versions, corpora and protocols differ between experiments; do not combine their percentages or treat older output as validation of the current redaction/workflow version. No model-quality gain is established by the cache experiment.

## Retrieval-only Redis experiment

Source: [cache-benchmark.json](cache-benchmark.json), generated by [scripts/benchmark_cache.py](../scripts/benchmark_cache.py). Real locked CPU MiniLM encoder, PostgreSQL/pgvector and Redis; 13 reviewed documents and 32 passages. Each main workload has 40 sequential requests per mode in a fixed mode order. Four initial cold queries are descriptive and excluded from claims about stable percentiles.

| Workload | Cache disabled p50 | Both cache layers p50 | Requests per mode |
|---|---:|---:|---:|
| Warm repeated queries | 9.245 ms | 1.694 ms | 40 |
| Unique queries | 9.781 ms | 12.466 ms | 40 |

Warm median decreased 81.7%; unique-query median increased about 27.4%. All returned results were compared for equality. This is retrieval-only latency, measured locally in one sequential process, excluding hosted inference and whole-investigation work. It is not a concurrency/capacity claim or evidence of generative token savings. Cache stays optional and off by default. Historical instrumentation differs from the current diagnostics code; these results were not rerun during release cleanup.

## Frozen held-out retrieval study

Source: [heldout.json](../evaluation/results/heldout.json), `variants.*.summary`, with [selection lock](../evaluation/results/selection-lock.json), [protocol](../evaluation/STUDY.md) and [full historical report](RAG_QUALITY_STUDY.md). Forty authored questions were divided into 20 development and 20 held-out questions by family. Held-out contains 15 answerable and 5 absent-knowledge questions. Methods shared the expanded 15-document evaluation corpus, including two explicitly fictional applicability distractors. The authoring assistant created documents, questions and labels; this is not an independent dataset.

| Method | Section Recall@5 | MRR@5 |
|---|---:|---:|
| Frozen hybrid | 86.7% | 0.844 |
| Preserved formatting, baseline ranking | 86.7% | 0.844 |
| Development-selected query shaping + diversity | 90.0% | 0.789 |

The selected experimental profile was **not promoted**: recall increased while ranking quality declined and a guidance section found by the baseline was missed. Selecting a different profile after seeing held-out results would reuse test information for selection. Recall averages relevant-section coverage over answerable questions; it does not measure whether a generated report reaches a correct causal conclusion. PostgreSQL FTS here is an intentionally simple AND-query baseline, not BM25.

## Four-case development pilot

Source: [development-pilot.json](../evaluation/diagnosis-v2/results/development-pilot.json), [review.json](../evaluation/diagnosis-v2/results/review.json) and [pilot protocol](../evaluation/diagnosis-v2/PROTOCOL.md). This newer fixed-evidence study used four controlled development cases and three methods, making 12 calls with 61,104 provider-reported tokens and 177,851 serialized input bytes.

| Method | Structurally/reference-valid reports |
|---|---:|
| Logs only | 4/4 |
| All applicable context | 3/4 |
| Baseline RAG | 4/4 |

A runbook passage ID incorrectly used as an observation ID was rejected. Same-assistant qualitative review found incomplete per-claim citations, an unsuitable database follow-up and ambiguous originating-service semantics. Structural validation is not semantic entailment. **No RAG superiority was established.** This pilot is distinct from the earlier four-question/sixteen-call historical answer study and from the later active workflow comparison.

## Incomplete production-code workflow comparison

Sources: [workflow protocol](../evaluation/diagnosis-v2/WORKFLOW_PROTOCOL.md), [development results](../evaluation/diagnosis-v2/results/workflow-development/results.json), [held-out results](../evaluation/diagnosis-v2/results/workflow-heldout/results.json) and [summary](../evaluation/diagnosis-v2/results/workflow-heldout/summary.json).

The planned comparison contained 52 episodes. Development stopped on its first provider timeout. A separate protocol qualification succeeded with 1,785 reported tokens. The reserved phase then stopped on provider error after 10 attempted episodes, 9 validated reports and 14 model starts, with 60,138 reported tokens. Unknown/error usage may be missing. Twelve captured cases remain untouched. Prior failures were not retried, replaced or dropped; no final method-superiority percentage is reported. The pilot's earlier zero-held-out-call count is historical and does not describe this later phase. Continuation requires a documented frozen protocol, not overwriting phase directories.

The attributed RCAEval Online Boutique excerpt has 120 records across six services and 0.5 seconds of declared coverage. ## How to reproduce the benchmark

Use a separate local checkout and generated local configuration. Prepare the locked model as described in the root README; never copy private runtime state. First run the README's complete integration-test command, which creates `investigator_test`. The benchmark uses its own random schema and cache prefix and removes only its own temporary resources. Do not use FLUSHDB or point tests at another application's database.

From the repository root in PowerShell:

```powershell
New-Item -ItemType Directory -Force work | Out-Null
docker compose -p investigator-checks -f compose.yaml -f compose.knowledge.yaml -f compose.cache.yaml -f compose.verify.yaml --profile verification run --rm -e KNOWLEDGE_MODEL_DIR=/models/minilm -v "${PWD}/data/embeddings/minilm:/models/minilm:ro" verify python scripts/benchmark_cache.py --trials 40 | Set-Content -Encoding utf8 work/cache-reproduction.json
```

This is a new local measurement; do not overwrite `docs/cache-benchmark.json` or claim that its exact timings must reproduce on different hardware. The script's measured modes are cache disabled, embedding-only and both layers; output also reports cold/warm/unique phases and response equality.

For retrieval-study mechanics, [evaluation/run.py](../evaluation/run.py) refuses to overwrite recorded results and verifies frozen input hashes. Use the separate-output mount described in [the historical study](RAG_QUALITY_STUDY.md) if deliberately reproducing already-seen questions. Those questions do not become unseen again. Hosted pilot/workflow runners require a separately approved budget and frozen continuation plan; release verification does not invoke them.

Run `python scripts/verify_documented_metrics.py` to check the documented rounded values/counts against source JSON without rewriting any result file. Automated structural and mechanical checks do not establish semantic faithfulness or independent usefulness.
