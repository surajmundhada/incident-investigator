# Release design decisions

These short ADRs describe the current release. Historical planning/qualification notes follow and retain their original scope; newer source changes do not retroactively change frozen studies.

## ADR: At-least-once jobs

Use PostgreSQL for atomic incident/job admission and leased work instead of a separate queue broker. A committed job can be reclaimed after interruption, so reads may repeat. Accept at-least-once execution; deduplicate admission and protect durable writes. A separate broker would add delivery and dual-write concerns before there is measured need.

## ADR: Fencing tokens

A lease timeout alone cannot stop an old process from writing after another worker claims its job. Every advancing write checks the token and unexpired lease. Cancellation and new ownership invalidate old attempts. Repeated external reads are still possible; external model requests with unknown outcomes stop rather than automatically retry.

## ADR: Exact vector search

The current reviewed corpus is small. Use exact pgvector cosine search with applicability filters, PostgreSQL FTS and RRF. Avoid approximate-index parameters and recall tradeoffs until corpus size and measured latency justify them. FTS uses plainto_tsquery/ts_rank_cd, not BM25.

## ADR: Cache default off

The recorded repeated-query workload benefited from cache hits, while unique-query median became slower. Keep Redis disposable and opt-in, with scope/revision/model-aware keys and bounded failure fallback. Do not add distributed cache locking to the correctness path. See evaluation.md for source-backed measurements.

## ADR: Migration 0008

Local and S3 exports may intentionally share an object key while remaining separate backend copies. Global object-key uniqueness rejected that valid combination. Migration 0008 enforces uniqueness on (backend, object_key); its downgrade refuses overlapping keys rather than deleting metadata. Frozen results and existing local objects are retained.

## ADR: Explicit configuration and local trust

Require explicit DATABASE_URL for host database processes; Compose constructs it from generated local credentials. Importing API code no longer creates a deployment connection: Uvicorn uses create_app with --factory. Keep every published Compose port on loopback and test that contract. No full authentication system is included; do not expose this local workspace to a network.

## ADR: Redaction release boundary

model-boundary-v3 adds AWS secret/session and alert-webhook aliases in assignment strings and nested dictionaries. New snapshots use the new boundary identity; old captures/reports remain immutable and retain their original provenance. Pattern redaction is not comprehensive privacy detection and does not rewrite original incident/live evidence or existing exports. Source-side privacy review remains necessary.

## ADR: S3 policy template

The public IAM policy uses ${ARTIFACT_S3_BUCKET}. The operator launcher validates the bucket name, renders the expected policy and compares actual permissions before obtaining scoped credentials. Download verification derives its expected regional host from configuration. No bucket/account identifier or credential is required in public source. Existing running launchers must be restarted explicitly to load changed source; release verification does not alter them.

# Design decisions

These decisions preserve the selected direction. They are not claims that the implementation exists. Each must be revisited if measurements contradict its assumptions.

## First slice verification boundary

Initially Docker was unavailable, so the schema and queue were developed with an explicitly labeled SQLite preview. Docker Desktop was subsequently installed per-user. PostgreSQL migrations and six database-specific checks now pass inside Docker. SQLite remains an optional preview, not the basis for PostgreSQL concurrency claims. The new container API uses localhost port 8001 to coexist with the earlier preview on port 8000.

The host has Python 3.13.1 and Node 20.19.0. Support Python 3.12â€“3.13 and retain Python 3.12 as the container target. The initial dependencies were downloaded into a project virtual environment and pinned in requirements.lock. No model calls or cloud provisioning occurred.

The first slice emits evidence-collection reports with no hypotheses or generated diagnosis. Fixture provenance is explicit. RAG and model reasoning will be added after this path is reliable.

## Live target increment

The first real target increment runs three small HTTP services with a single temporary payment-unavailability scenario. Checkout propagates bounded request IDs across inventory and payment. Logs are generated by actual request handling, with fixture/live provenance retained in the existing evidence schema. This is request correlation, not distributed tracing.

Use capped rotating JSONL and a read-only log-source adapter before adding the full telemetry stack. This keeps the increment small on the 16 GB machine. Rotation marks coverage as potentially truncated; corrupt or unreadable files are unavailable, not healthy. Simple per-process metrics are exposed but are not yet collected by Prometheus or an investigator metric tool. Add full telemetry only in a qualified increment.

The shopping simulation has no durable business records yet. A separate target database is deferred until a scenario requires it; PostgreSQL currently belongs to the investigator. Do not claim database failure diagnosis from a service-unavailability test.

The operator controller has its own network and a short-lived setting volume, mounted read-only by payment. The worker reaches the evidence source but has no target/controller network or control-volume mount. No fault mode or expiry is written into agent-visible telemetry. This separates experimental ground truth from observable symptoms for later evaluation.

## Independent implementation

Build independently, using Aurora and HolmesGPT as references. Extending an existing project could provide integrations sooner, but would increase inherited code and make end-to-end ownership harder to explain. Verify through clear attribution and a traceable implementation.

## Local deployment with S3

Use Docker Compose locally and a private S3 bucket for objects. A public AWS deployment adds hosting, authentication, and operational work before diagnosis quality is established. Revisit when external users or a public demonstration require it. No AWS resources exist yet.

## Relational state plus vector retrieval

PostgreSQL owns transactional state and relationships; pgvector adds semantic retrieval. JSONB handles variable tool payloads. A separate vector database or document database is possible, but not required by the initial corpus. Verify transactions, constraints, retrieval behavior, and latency. Split stores only when measured requirements justify it.

## Implemented retrieval increment

Retain the planned all-MiniLM-L6-v2 baseline using FastEmbed 0.9.1 and ONNX CPU rather than the full Sentence Transformers/PyTorch runtime. Pin the ONNX repository commit, file checksums, runtime dependencies, and pooling behavior. Explicit preparation downloads public weights; inference is local and offline. Use an optional Docker build stage so target services do not inherit the embedding runtime.

Publish a complete immutable corpus in one PostgreSQL transaction, with a schema-scoped advisory lock and an active revision pointer. Compute embeddings before opening the publication transaction. Retain prior passage rows so saved citations remain resolvable. Failed indexing leaves the active revision unchanged; old revision cleanup is deferred.

Use weighted PostgreSQL full-text search and exact cosine vector search, filtered before ranking by environment/release/service plus global guidance. Fuse up to 20 candidates per channel with reciprocal rank fusion and cap returned context. There is no approximate index or reranker at this corpus size. The first lexical baseline ANDs normalized terms; development results must acknowledge that limitation.

Persist runbook results separately from live observations and reuse them on worker recovery. Runbook content suggests checks and does not establish current incident facts. This increment implements retrieval, not model-backed diagnosis. See RETRIEVAL.md for the implemented bounds, verification, and remaining gaps.

## RAG experiment and rollout hold

Preserve the original implementation with checksums and compare on the same expanded corpus in an isolated database. Lock development and held-out questions before measuring; select on development results and do not retune after held-out results. Authored data and assistant review remain explicitly internal, not independent benchmark evidence.

The query/diversity profile improved development ordering, but held-out recall and ordering moved in different directions. Keep baseline ranking as production default rather than selecting the stronger query-only test result after seeing it. The local MiniLM reranker improved absent-knowledge rejection but lost relevant sections and failed the development recall gate, so it is not the default. See RAG_QUALITY_STUDY.md for full tables and failures.

Deploy correctness improvements independently: persist incident applicability, preserve old hash identities, reject unsupported live-log scopes, pin knowledge revision/profile across agent searches, and preserve Markdown whitespace/source lines. Keep experimental ranking choices explicit. Do not present these as proof of higher diagnosis accuracy.

The sixteen-call fixed-context answer comparison did not demonstrate a RAG quality advantage on this small example. Valid citation IDs were insufficient for complete per-claim support. Separate deterministic reference validation from semantic review. Two rejected bodies were not retained by the original runner; disclose that loss and retain raw actions in future versioned studies rather than recreating missing outputs.

## Model boundary and dashboard increment

Keep authorization in application code and test hostile model decisions directly. Supply a small reviewed architecture block on every native request, scoped to the known local demo release. Retrieved prose remains untrusted even when versioned. Add best-effort credential redaction at the outbound model boundary while retaining original local evidence for provenance. This does not sanitise database/API/export contents or establish injection resistance. See SECURITY.md.

Build the first dashboard with the planned React/TypeScript/Vite stack and local CSS rather than adding a styling dependency. Use the existing ordered event API with bounded polling before introducing SSE. Preserve request identity across unchanged form retries, escape generated text, and keep fault controls outside the investigation interface. Browser tests are mocked and quota-free; a separate read-only live check distinguishes actual connectivity. See DASHBOARD.md.

The user chose a polished SaaS dashboard direction after reviewing the initial UI. Replace the marketing-style welcome and long incident-list sidebar with a functional overview and compact navigation. Show counts only for actually loaded cases, use explicit API readiness language, and keep the illustrative investigation flow separate from live telemetry. Use client filtering/pagination within the latest 100 until a broader archive is needed. Keep generation and evidence rendering unchanged, with safe text rendering and existing retry/citation checks.

## Reusable application configuration and captures

Prioritise another developer's onboarding path before caches/object storage. Replace application-specific service enums with validated IDs and persist immutable topology revisions plus active scope pointers. Pin a configuration at incident admission. Derive tool permissions from the root and its direct registered dependencies, without letting tool results expand that boundary. Do not accept arbitrary HTTP URLs or free-text system instructions in configuration.

Use bounded JSONL-to-JSON ingestion as the first external evidence interface. Store immutable, recognised-pattern-redacted snapshot records in PostgreSQL with declared coverage/provenance, then reuse the existing worker/tool/report path. Source checksums identify the canonical parsed payload; they do not establish completeness or authenticity. Do not treat a missing service export as an empty healthy result, and never fall through to shopping logs for another application. S3/raw archive and generic live connectors remain separate increments.

Filter runbook heads, candidates, explicit revisions and citations by application. Global guidance is shared within an application, not across all registered applications. Preserve historical revision rows and v1/v2 idempotency identities. This is local workspace data scoping, not tenant authentication. The synthetic connected examples verify onboarding/persistence; actual-model diagnosis and independent developer benefit still require separate evaluation.

## Optional Redis implementation

Redis now caches only application-scoped embeddings and immutable revision-scoped runbook retrieval. Defer observations and diagnoses to avoid stale incident evidence and ownership confusion. Resolve revision/model identity in PostgreSQL before cache lookup, version/hash complete scopes, validate payloads, batch embeddings and fail open with bounded timeouts/no retries/five-second bypass. A stopped-container check exposed DNS outside socket timeouts; bound the entire caller wait with a capped executor. Use local striped coalescing, accepting cross-process duplicate computation instead of Redis correctness locks. Keep the cache optional and disabled by default: final warm repeated hybrid median improved 81.7%, while unique-query median became about 27.4% slower. See CACHE.md and actual benchmark data; these results do not establish production savings.

## Readiness and alert admission

Compose now checks /readyz over HTTP, rather than treating a running API process as ready. Encoder startup can outlast an arbitrary short sleep; Redis is excluded from readiness. Keep normalized alert admission token-gated and off by default. Require stable occurrence identity and a closed window so retries reuse the same incident input; changing input conflicts rather than silently moving the evidence window. Native Alertmanager adaptation is deferred. See ALERTS.md.

## Durable events with SSE and polling fallback

Expose committed ordered database events through bounded SSE streams. Reuse database IDs as resume cursors; drain terminal pages and retain JSON polling as a transport fallback. A terminal report can overtake the final streamed event, so the UI explicitly drains saved events on completion. Keep one-way EventSource rather than WebSockets, and PostgreSQL polling rather than another pub/sub correctness path. See PROGRESS_STREAM.md.

## Operator Markdown publication

Expose a bounded complete-corpus upload for a registered application/configuration. Generate filenames, redact recognised credentials before embedding, reuse existing chunking/atomic publication and retain historical citations. Require an explicit whole-application replacement acknowledgement and an expected revision; compare under the publication advisory lock so competing publishers cannot silently overwrite. Indexing is limited to one request per API process, not a durable ingestion queue. Full original-document archiving remains separate artifact work. Uploaded runbooks stay untrusted guidance and cannot add trusted architecture instructions or tool permissions.

## S3 for artifacts

The user created/reported ${ARTIFACT_S3_BUCKET} in ap-southeast-2. Preserve that region rather than create another bucket. Prepare prefix-scoped GetObject/PutObject and read-only bucket checks. Include ListBucket on this dedicated bucket because HeadObject returns 403 rather than 404 for missing objects without it; do not convert arbitrary access denial into a successful miss. This reveals bucket object names, a disclosed tradeoff. Prefer temporary CLI browser-login credentials over root keys; host CLI refresh does not automatically refresh credentials exported into Docker. Runtime stays local until authentication/privacy checks and a bounded real round trip are qualified. See S3_CONNECTION.md.

The initial artifact slice exports terminal investigations/report/evidence on operator request. Keep PostgreSQL authoritative for pending/available/failed metadata, with a flushed atomic local spool, stable content-addressed keys, bounded leased delivery and checksum reconciliation. Verify an already-uploaded object before retrying after a crash; fence stale owners. Identical exports reuse identity. Missing spool can be reconstructed only if the terminal records still match the original checksum.

Provide a real local filesystem backend so recovery works without an AWS account. Implement S3 through the same interface, with explicit checksums, server-side encryption and short signed downloads, but keep actual cloud qualification separate. User requested notification when AWS connection is needed; no resources or costs are authorized merely by implementing the adapter. Original source-document archival, automatic retention/spool cleanup and external deletion reconciliation remain deferred. See ARTIFACTS.md.

## PostgreSQL jobs initially

An incident and its job can be committed together. A Redis broker/Celery design is a valid alternative, including Aurora's documented approach, but would introduce broker delivery and dual-write concerns. Begin with database claims, leases, fencing, bounded retries, and durable checkpoints. Reconsider if queue throughput or scheduling complexity becomes a measured bottleneck.

## One bounded agent

Use an explicit LangGraph workflow instead of several role-based agents. This reduces cost and makes trajectories easier to debug and compare. Verify tool limits, valid transitions, stopping behavior, and recovery. Add another agent only for an independently demonstrated benefit.

### Implemented state ownership and provider loop

LangGraph now controls the plan/action loop, while application-owned checkpoint rows are saved through the existing lease-fenced repository. A native saver on a separate connection would not inherit those ownership checks automatically. Keep one authoritative transactional state path for now; native saver integration is deferred, not claimed as implemented.

Reserve model usage before each request. An interrupted request with no durable outcome stops as unknown instead of being repeated automatically. A saved validated action may resume, and a committed tool result is reusable. Repeated uncommitted reads are possible; no exactly-once claim is made. Cancellation locks the same job row and invalidates ownership before changing investigation state.

The model chooses one native function per fresh request over explicit evidence/state. Code executes the read-only action; no SDK can automatically execute tools or arbitrary commands. Enforce fixed windows and reviewed dependency scope. Validate observation indices and retrieved passage references, acknowledging that reference validity does not establish semantic support.

## Structured live tools and document RAG

Retrieve runbooks and architecture notes; query live signals through typed tools. Embedding all raw logs is unnecessary for structured time-window queries. Verify that retrieved procedures are applicable and every observation preserves source/window metadata. Do not describe PostgreSQL keyword search as BM25.

## Read-only tools

Diagnosis quality is the first objective. Automatic fixes and arbitrary shell execution create additional permission and recovery problems. Verify credentials and tool allowlists rather than relying on prompt instructions. Remediation requires a separately designed phase.

## MCP after internal tool interfaces

Expose existing local API reads through an optional stdio MCP facade: saved investigations, registered topology and scoped runbook search. Do not expose admission, remediation or arbitrary destinations. Reuse SearchRequest and API behavior, bound responses, redact recognized credentials and label returned data untrusted. Local host access means workspace read access, not tenant authentication. MCP is interoperability, not a second agent or quality improvement. SDK/host qualification is separate from proxy tests. See MCP.md.

## Deferred infrastructure

MCP SDK tests exposed missing structured output for a bare dict return. Use explicit Pydantic response models so protocol clients receive a validated schema and structured content. In-memory, real stdio and connected local-API checks now pass. Third-party MCP host setup remains separate.

No Memgraph, Vault, or Kubernetes initially. Store the small reviewed dependency map in application data. Use server-side environment configuration and scoped AWS credentials. Revisit Kubernetes for cluster-specific diagnosis or demonstrated multi-node hosting needs; revisit graph storage or secrets management when concrete requirements justify them.

Add a separate bounded native Alertmanager version-4 endpoint while preserving the normalized endpoint. Require explicit scope/source and a stable closed-window annotation pair; never derive a moving evidence end from notification receipt or changing endsAt. Validate the batch shape before admission, then reuse atomic per-incident/job admission and disclose per-alert batch commits. Exact retries reuse jobs, changed input conflicts, and resolved entries do not cancel investigations. URLs in deliveries never become tool destinations. No monitor server or subscription is provisioned.

Capture all three service logs through the read-only evidence API before any agent trajectory, keep labels out of application images, freeze hashes and explicitly call repeated controlled instances synthetic rather than independent production incidents.

Expose aggregate historical RAG/cache measurements in an Evaluation page, generated from source artifacts with hashes. Do not expose questions or ground-truth labels. The production ranking/cache defaults remain unchanged. ## Cache operator observability

Reuse process-local CacheMetrics rather than introduce a monitoring dependency into retrieval. The API diagnostics route returns whitelisted counters, instance/observation timestamps and bounded 512-sample success latency distributions for hit/miss-or-fallback/uncached paths. Search responses remain unchanged. Polling takes only local locks and never contacts Redis; enabled is configuration, not a health claim. Cache-read failures still fail open, and diagnostics do not gate correctness or readiness.

Keep activation as an operator-controlled startup choice. The UI explains matched-workload comparisons, unknown/empty measurements, API-only scope, restart resets and the S3 watcher's ability to restore its startup configuration. No automatic threshold or browser Docker control is justified by the small historical benchmark. Exclude worker/indexer totals and server memory until a separately designed aggregation/resource monitor exists, rather than label partial observations global. Exported snapshots are manual evidence, not durable monitoring history. See CACHE.md.

## Report-origin semantics and narrow citation consistency

Candidate v5 defines hypothesis.service as the hypothesized originating service, not merely the affected caller; healthy observations should not become causal hypotheses. Ask for narrow claims with all direct records, particularly caller completion plus dependency evidence. Code rejects explicit HTTP/status-code statements absent from their direct citations and hypotheses unanchored to their service/dependency records. This intentionally narrow consistency check is not a semantic faithfulness judge; do not promise complete entailment or manufacture an accuracy percentage.

Freeze source/protocol/corpus/model before using reserved cases. The production-code replay stopped on provider errors, preserving the unknown/failed episodes without retry. Nine completed reports are not a completed sixteen-case comparison. Keep incomplete phase outputs and disable final percentage publication. Do not adjust prompts/rankers from held-out observations.

## S3 watcher failure and bounded operator recovery

An actual scheduled renewal succeeded, but a later AWS CLI error terminated the earlier watcher. Add one OS-held launcher lock to prevent competing watchers restoring different cache modes; lock release follows process lifetime. Bound preflight as a whole to two minutes. Retry only classified transient renewal errors at most four attempts with 10/20/40-second backoff; stop near old credential expiry. Expired credentials, permission/configuration changes and initial startup failures remain explicit operator actions. Record sanitized last-observed state and successful renewal count, never credentials. This increases tolerance without claiming an OS service or unattended production availability. New guards have unit coverage; no full timed cycle of the revised watcher is claimed yet.
