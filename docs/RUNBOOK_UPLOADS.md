# Publish application guidance

Choose a registered configuration on the dashboard's Applications page. Select the complete set of Markdown files, edit document IDs/titles/service applicability, acknowledge whole-application replacement, then Publish runbooks. The selected configuration supplies application, environment and release. Global means all services within that application only.

This first upload interface replaces the application's active corpus across all environments/releases with the selected scope's documents. It is explicitly a complete replacement, not an append operation. Supply all required guidance or continue using the operator manifest CLI for a multi-scope corpus. Historical chunks/citations remain available. Do not replace the shopping reference corpus casually; the local verification scripts publish only new synthetic applications.

The API exposes GET `/api/knowledge/head?application=...` and POST `/api/knowledge/documents`. The latter accepts application, configuration_revision, required nullable expected_revision, replace_application_corpus=true, and documents with id/title/service/markdown. Null expected_revision means no prior head; a stale head returns 409. Repeating an identical published corpus is idempotent. Configuration and service membership are checked before embedding; arbitrary client paths and URLs are not accepted.

Limits: up to fifty files, 100 KB per UTF-8 document, 1 MB total Markdown and a 1.1 MB streamed JSON request. Existing chunking enforces heading/model/context budgets and a maximum passage count. Only one upload indexes per API process; concurrent requests receive 429. This is bounded synchronous local indexing, not a durable upload queue. A failed request may still finish publication if the client disconnects after commit; reload/retry with the same corpus rather than assume cancellation.

Recognised credential patterns are redacted before indexing and cache writes. Checksums/lines describe the redacted normalized Markdown. Redaction is best effort; review documents first. Plain Markdown remains untrusted guidance, rendered as text in the dashboard and separated from reviewed system context. The existing model/tool permissions are unchanged.

Embeddings are prepared before the publication transaction. Under the schema-scoped advisory lock, the expected head is checked, immutable revision/chunks are inserted, and the active pointer changes atomically. A race or failed embedding preserves the prior head. Cache keys include the resolved revision, so no mass invalidation is needed. The original full documents are not archived by this interface yet; keep their source files. Archive exports currently preserve the investigation/report/evidence, not a document-management repository.
